# TD-003: Template-Based Config Generation

## Overview

**Status**: In Progress  
**Priority**: Medium  
**Estimated Effort**: 2-3 hours

### Problem Statement

The `manifest.yaml`, `orchestra.yaml`, and `progress.yaml` files are currently generated from inline code strings in `src/commands/init.ts`. This violates the template architecture principle stated in TEMPLATE_REGISTRY.md: **"NOTHING should be inline in source"**.

### Current State

1. `manifest.yaml` - Generated by `generateManifestTemplate()` function with inline template string
2. `orchestra.yaml` - Generated from `DEFAULT_CONFIG` object serialized to YAML
3. `progress.yaml` - Generated by `generateProgressTemplate()` function with inline template string

### Proposed Solution

Create Handlebars templates for all config files and use the existing `templates.ts` infrastructure to render them during init.

## Technical Design

### New Files

```
templates/common/templates/
├── manifest.yaml.hbs       # Sprint manifest template
├── orchestra.yaml.hbs      # Configuration template  
├── progress.yaml.hbs       # Progress tracking template
```

### Template Structure

#### manifest.yaml.hbs

```handlebars
# Orchestra Manifest - Generated {{today}}
{{#if specPath}}
# SpecKit Root: {{specPath}}
# This manifest tracks implementation of SpecKit tasks
{{else}}
# TODO: Add speckit.root to orchestra.yaml
{{/if}}

version: "{{version}}"

sprint:
  id: "{{sprint.id}}"
  name: "{{sprint.name}}"
  status: {{sprint.status}}
  created_at: "{{today}}"

phases:
  - phase_id: "foundation"
    phase_name: "Foundation Phase"
    status: ACTIVE
    speckit_tasks:
      - "T001"
      - "T002"
    tasks:
      - task_id: 1
        title: "First Task"
        description: "TODO: Describe what needs to be done"
        status: PENDING
        category: INFRASTRUCTURE
        dependencies: []
        speckit_task_ref: "001-foundation/tasks.md#T001"

      - task_id: 2
        title: "Second Task"
        description: "TODO: Describe what needs to be done"
        status: PENDING
        category: INTEGRATION
        dependencies: [1]
        speckit_task_ref: "001-foundation/tasks.md#T002"

consolidations: []
```

#### orchestra.yaml.hbs

```handlebars
# Orchestra Configuration - Generated {{today}}
# See documentation for all available options

version: "{{version}}"

paths:
  manifest: {{paths.manifest}}
  handovers: {{paths.handovers}}
  feedback: {{paths.feedback}}
  artifacts: {{paths.artifacts}}
  templates: {{paths.templates}}

{{#if specPath}}
speckit:
  root: "{{specPath}}"
{{/if}}

git:
  auto_stage: {{git.auto_stage}}
  auto_commit: {{git.auto_commit}}
  commit_prefix: "{{git.commit_prefix}}"
```

#### progress.yaml.hbs

```handlebars
# Orchestra Progress Tracker - Generated {{today}}
# This file tracks task execution and completion

sprint_id: "{{sprint.id}}"
created_at: "{{today}}"

entries: []
```

### Implementation Changes

#### 1. Create new core function: `src/core/config-generator.ts`

```typescript
export interface ConfigTemplateContext {
  today: string;
  version: string;
  specPath?: string;
  sprint: {
    id: string;
    name: string;
    status: string;
  };
  paths: {
    manifest: string;
    handovers: string;
    feedback: string;
    artifacts: string;
    templates: string;
  };
  git: {
    auto_stage: boolean;
    auto_commit: boolean;
    commit_prefix: string;
  };
}

export function createDefaultContext(specPath?: string): ConfigTemplateContext;
export function generateManifestYaml(context: ConfigTemplateContext): string;
export function generateOrchestraYaml(context: ConfigTemplateContext): string;
export function generateProgressYaml(context: ConfigTemplateContext): string;
```

#### 2. Update `src/commands/init.ts`

- Remove `generateManifestTemplate()` inline function
- Remove `generateProgressTemplate()` inline function
- Import and use functions from `config-generator.ts`
- Render templates instead of using inline strings

#### 3. Update template loading

The templates need to be loaded from the package's `templates/` directory during init (before `.orchestra/` exists), not from `.orchestra/common/templates/`.

### Template Rendering Flow

```
init command
  ↓
createDefaultContext(specPath)
  ↓
renderPackageTemplate('manifest.yaml', context)  # From templates/common/templates/
  ↓
Write to .orchestra/manifest.yaml
  ↓
Copy .hbs files to .orchestra/common/templates/
```

### Key Functions

#### loadPackageTemplate()

Load templates from the npm package's `templates/` directory (for use during init when `.orchestra/` doesn't exist yet).

#### renderPackageTemplate()

Render a template from the package directory with given context.
