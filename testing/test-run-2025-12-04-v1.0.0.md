### Issue #4: Script vs CLI pre-signal artifact location mismatch (FIXED)

| Field | Value |
|-------|-------|
| **Severity** | HIGH |
| **Type** | Integration Bug |
| **Status** | ✅ FIXED |

**Description:**
The battle-tested `pre-signal-check.ps1` script was writing artifacts to:
- `.orchestra/implementor/artifacts/pre-signal/task-{id}-{timestamp}.txt`

But CLI (`orchestra accept-signal`) expects:
- `.orchestra/handover/verification/pre-signal.yaml`

**Root Cause:** Script evolved separately from CLI spec.

**Fix Applied:** Updated `pre-signal-check.ps1` to write BOTH:
1. **Fixed location** (CLI): `.orchestra/handover/verification/pre-signal.yaml`
2. **Audit trail** (archive): `.orchestra/implementor/artifacts/pre-signal/task-{id}-{timestamp}.yaml`

Both now use YAML format. CLI is unchanged - script was updated to match.

### Issue #5: verify/complete report path mismatch (CRITICAL)

| Field | Value |
|-------|-------|
| **Severity** | CRITICAL |
| **Type** | Integration Bug |
| **Status** | Open |

**Description:**
`orchestra verify` saves verification reports to:
- `.orchestra/reports/verification/task-{id}-{timestamp}.json`

But `orchestra complete` looks for reports at:
- `.orchestra/orchestrator/results/task-{id}-verification.yaml`

**Impact:** `complete` always fails without `--force` because it can't find the verification report.

**Root Cause:** Different file paths and formats (JSON vs YAML) between commands.

**Fix Options:**
1. Update `verify` to also write to location `complete` expects
2. Update `complete` to look in location `verify` writes
3. Standardize on one location/format

**Workaround:** Use `orchestra complete --force`
