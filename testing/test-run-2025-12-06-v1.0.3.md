## Issues Found

### Issue 1: No guidance when Orchestra not initialized

**Severity**: Medium  
**Status**: Open  
**Category**: UX/Onboarding

**Description**:
When Orchestra is not initialized in a workspace, there's no helpful guidance for agents/humans. Need either:
1. `orchestra status` to work gracefully and show setup instructions, OR
2. `orchestra guide` command that provides setup, usage, and first/next step guidance

**Current Behavior**:
- `orchestra status` fails with error if not initialized
- No clear path for new users/agents to understand what to do

**Expected Behavior**:
- Running `orchestra status` (or a new `orchestra guide` command) should:
  - Detect Orchestra is not initialized
  - Explain what Orchestra is
  - Show how to initialize (`orchestra init`)
  - Guide to next steps

**Proposed Solutions**:
1. **Option A**: Make `orchestra status` graceful - show "Not initialized" state with guidance
2. **Option B**: Create `orchestra guide` command for onboarding
3. **Option C**: Both - status shows state, guide shows detailed help

**Related**:
- `orchestra next` already provides guidance once initialized
- This is the pre-initialization equivalent

### Issue 4: validate-handover and pre-signal-check using wrong path

**Severity**: Critical  
**Status**: Fixed  
**Category**: Path Bug

**Description**:
`orchestra validate-handover` was looking for handover file at wrong path. The error showed:
```
Error: Handover not found: E:\...\orchestra\handover\current-task.md
```

But the correct path should be:
```
E:\...\orchestra\.orchestra\handover\current-task.md
```

**Root Cause**:
In `src/core/validate-handover.ts` and `src/core/pre-signal-check.ts`, the code was using:
```typescript
const handoverPath = path.join(orchestraRoot, "handover", "current-task.md");
```

But `requireOrchestraRoot()` returns the repo root (e.g., `E:\repo`), not the `.orchestra` directory. The path should have been:
```typescript
const handoverPath = path.join(orchestraRoot, ".orchestra", "handover", "current-task.md");
```

Additionally, `pre-signal-check.ts` had another bug:
```typescript
const repoRoot = path.resolve(orchestraRoot, "..");  // WRONG - goes up a directory
```

This should be:
```typescript
const repoRoot = orchestraRoot;  // orchestraRoot IS the repo root
```

**Files Fixed**:
1. `src/core/validate-handover.ts` - Added `.orchestra` to handover path
2. `src/core/pre-signal-check.ts` - Fixed path, fixed repoRoot assignment
3. `test/core/validate-handover.test.ts` - Fixed test mocks to match correct behavior

**Test Impact**:
The tests were also incorrect - they mocked `requireOrchestraRoot` to return the `.orchestra` directory path instead of the repo root. This masked the bug.

### Issue 5: Template missing Deliverables and TDD sections required by validator

**Severity**: High  
**Status**: Fixed  
**Category**: Template/Validator Mismatch

**Description**:
After running `orchestra prepare` for Task 1, the generated handover failed validation because it was missing the `## Deliverables` and `## TDD` sections that the validator requires.

**Validation Output**:
```
✗ Has deliverables section
  No deliverables section - what files to create/modify?

✗ Has TDD/testing section
  No testing section - what tests to write?
```

**Root Cause Analysis**:

1. **Detailed spec exists**: `spec/implementation/phase-2-mcp/tasks/2.1-project-setup.md` had full deliverables, code scaffolds, and success criteria.

2. **Template was too minimal**: `current-task.md.hbs` only rendered:
   - Task title/description
   - Spec file reference (says "read the spec file for full details")
   - Generic validation/completion instructions

3. **Missing required sections**: The template didn't include:
   - `## Deliverables` section header
   - `## TDD` / `## Testing` section header

4. **Design mismatch**: Template philosophy was "reference the spec" but validator expected self-contained handover.

**The Chain of Failure**:
- Orchestrator followed template correctly
- Template didn't generate required sections
- Validator correctly failed because sections were missing
- **Not an orchestrator execution error** - it's a template design bug

**Fix Applied**:
Updated `current-task.md.hbs` to include:
1. `## Deliverables` section - shows file operations table if available, otherwise references spec file
2. `## TDD / Testing` section - shows test requirements if available, otherwise references spec file

The template now generates valid handovers that pass validation even when detailed file operations aren't in the manifest (references spec file as fallback).

**Files Changed**:
- `templates/common/templates/current-task.md.hbs`
- `.orchestra/common/templates/current-task.md.hbs`

**Future Enhancement**:
Consider adding `file_operations` and `test_requirements` fields to manifest schema so handovers can be fully self-contained without referencing spec files.
